# E-021 — Popraw kontrast i czytelność bazowego UI

Cel: użytkownik może odczytać drobne etykiety i objaśnienia statycznego ekranu także przy słabszym widzeniu; bazowe style spełniają minimalny kontrast WCAG AA bez utraty układu telefonu.

Zakres: `apps/web/src/styles.css` oraz raport w `handoffs/E-021-ui-readability.md`. Nie zmieniaj przepływu API, treści naukowych ani obliczeń.

## Kroki

1. Zmierz pary kolorów tekstu i tła faktycznie używane przez statyczny ekran; zapisz wartości przed poprawką.
2. Podnieś kontrast poniżej 4.5:1 dla zwykłego tekstu i popraw najdrobniejsze objaśnienia oraz podpisy, zachowując hierarchię wizualną.
3. Sprawdź produkcyjny build i szerokości 320/375/390/780/782/1150/1151 CSS px; zapisz pomiary i ograniczenia. Jeśli żądane 781 px daje inną rzeczywistą szerokość, nie przedstawiaj jej jako pomiaru 781 px.
4. Re-review K-030 wykazało, że żądane 781 px dało faktycznie `innerWidth=782`. Proponowany zakres weryfikacji zastępczej obejmuje dokładnie 780 i 782 px po obu stronach breakpointu 780 px; K-037 ma ocenić tę zmianę kryterium. Żaden wpis nie może twierdzić, że zmierzono dokładnie 781 px.

## Kryteria odbioru

- [x] Zwykły tekst ma kontrast co najmniej 4.5:1 z rzeczywistym tłem; 39 par bazowych i dodatkowe pary po synchronizacji mają minimum 4.68:1, w tym disabled UI.
- [x] Drobne etykiety, jednostki i objaśnienia są łatwiejsze do odczytania; audyt CSS/TSX po uwzględnieniu mobilnych nadpisań nie znajduje tekstu poniżej 9 px, a nadal aktywne wiersze niezaznaczonych kryteriów nie są sztucznie przygaszane.
- [ ] Przy siedmiu wskazanych szerokościach (320/375/390/780/782/1150/1151) nie ma poziomego overflow, uciętego tekstu ani nachodzących etykiet; fokus klawiatury nadal jest widoczny. Pomiar 782 px zastępuje nieosiągalne żądanie 781 px i wymaga akceptacji K-037; pomiarów renderu po aktualnej synchronizacji nadal brakuje.
- [x] `npm run build --prefix apps/web` przechodzi; handoff podaje pary kolorów, kontrast przed/po, sprawdzone szerokości i ograniczenia.

## Sprawdzenie

Oblicz kontrast z luminancji sRGB dla użytych par foreground/background. Zbuduj produkcyjny frontend i obejrzyj go przy 320, 375, 390, 780, 782, 1150 i 1151 CSS px, w tym przy klasycznym pasku przewijania. Potwierdź `scrollWidth <= clientWidth` oraz widoczny fokus klawiatury. Gdy dokładny viewport nie jest dostępny, zapisz żądaną i faktycznie raportowaną szerokość; nie deklaruj pomiaru 781 px na podstawie 782 px.

## Powód dodania / wpływ

Ręczny pomiar istniejącego `apps/web/src/styles.css` wykazał poniżej 4.5:1 m.in. stopkę (#687771 na #11191a: 3.79:1), drobny tekst pomocniczy panelu (#6d7d78 na #172122: 3.80:1), podpisy narzędzi (#71807c na #11191a: 4.31:1) oraz jednostki (#778782 na #172122: 4.36:1). Są to zwykłe teksty mniejsze niż duży tekst, więc utrudniają odczyt wymaganych stanów i ograniczeń produktu. WCAG 2.2 SC 1.4.3 podaje próg 4.5:1 dla zwykłego tekstu; [źródło W3C](https://www.w3.org/TR/2023/REC-WCAG22-20231005/). To ograniczona poprawka bazowego ekranu i nie zastępuje pełnego audytu interaktywnego UX w E-008.
