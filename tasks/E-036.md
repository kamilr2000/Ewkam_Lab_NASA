# E-036 — Utrzymaj stan warstw przy wyborze piksela i ponownym przeliczeniu

Cel: zapewnić, że trzy przełączniki mapy pozostają zgodne z widokiem przy wyborze innego piksela i po ponownym przeliczeniu Live analysis.

Zakres: `apps/web/src/map/AnalysisMap.tsx`, `apps/web/src/map/layerVisibility.ts` i testy mapy. Nie zmieniaj scoringu, parametrów zapytania ani wyniku API.

## Dlaczego

K-055 na prawdziwym wyniku i exact ref `f6eb210e91d389afc865cc10d4a7f0509c4d155a` odtworzył błąd: po odznaczeniu Ranked markers kliknięcie drugiego piksela rankingu pokazało 10 markerów mimo niezaznaczonego pola. Zmiana cech odmontowuje mapę podczas czyszczenia wyniku, więc po nowej analizie wszystkie przełączniki wracają też do wartości zaznaczonej. K-055 opublikował REQUEST_CHANGES na PR #96 (review ID `5912814749`).

## Kroki i kryteria odbioru

1. Zastosuj aktualny stan markerów po zmianie zaznaczonego piksela; odznaczone markery pozostają ukryte po kliknięciu innego wiersza rankingu.
2. Zachowaj wybór wszystkich warstw po zmianie cech, wyczyszczeniu poprzedniego wyniku i ponownym obliczeniu; wartości checkboxów mają zgadzać się z widocznością.
3. Dodaj regresje dla kliknięcia innego piksela przy ukrytych markerach i dla pełnego rerun flow.
4. Potwierdź, że zmiana widoczności nie modyfikuje rankingu, query ani `analysis_id`.
5. `npm test --prefix apps/web`, `npm run build --prefix apps/web` i `git diff --check` przechodzą.
