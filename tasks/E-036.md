# E-036 — Zachowaj ukryte markery po ponownym przeliczeniu

Cel: utrzymać wybór widoczności markerów, gdy Live search zastępuje listę pikseli po ponownym przeliczeniu albo zmianie zaznaczonego piksela.

Zakres: `apps/web/src/map/AnalysisMap.tsx`, `apps/web/src/map/layerVisibility.ts` i testy mapy. Nie zmieniaj scoringu, parametrów zapytania ani wyniku API.

## Dlaczego

W K-054 znaleziono, że efekt markerów usuwa i tworzy markery ponownie dla zmiany `pixels`/`selectedPixelId`, natomiast efekt nakładający `layerVisibility` zależy wyłącznie od `[layerVisibility, mapReady]`. Po wyłączeniu markerów i nowym wyniku nowe elementy DOM mogą pojawić się ponownie mimo odznaczonego przełącznika.

## Kroki i kryteria odbioru

1. Zastosuj bieżący stan widoczności do każdego tworzonego zestawu markerów.
2. Dodaj regresję: wyłącz markery, zastąp listę pikseli (symulując nowy wynik), potwierdź, że nowe markery pozostają ukryte; ponowne włączenie ma je pokazać.
3. Potwierdź, że przełącznik nie zmienia rankingu, query ani `analysis_id`.
4. `npm test --prefix apps/web`, `npm run build --prefix apps/web` i `git diff --check` przechodzą.

## Przebieg

Po zakończeniu i integracji E-035 jest to pierwsza kolejna praca Eweliny, jeśli czas demo pozwoli. Przed implementacją zarezerwuj kartę osobnym commitem na `origin/main`; nie ustawiaj teraz statusu `in_progress`.
