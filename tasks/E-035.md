# E-035 — Add an OSM basemap and independent result-layer controls

## Goal and scope

Show a recognizable geographic basemap below real regional results. Let users show or hide the basemap, result cells, and ranked markers independently. Preserve the existing criteria/weight selection and API rerun flow. The API remains the sole scoring engine.

Implementation: apps/web map component, layer styling and visibility state, focused regression tests, and web README source/usage notes. No satellite provider is included without an approved source, licence, and access method.

## Acceptance evidence

- [x] Real OSM street tiles render below result layers; visible attribution links to the OSM copyright page.
- [x] OSM, result-cell, and ranked-marker controls are independent and keyboard accessible. Visibility changes do not alter the API query, ranking, or analysis ID.
- [x] Criteria and weights are preserved; editing them clears the previous result, and rerun uses the selected body, profile, dataset, and region.
- [x] Post-fix browser evidence confirms a new analysis ID after rerun and consistent map/ranking/details.
- [x] Web tests, production build, and diff checks passed on the reviewed code ref. The MapLibre bundle still reports a large asynchronous chunk.
- [x] No satellite imagery or claim that OSM is a scientific analysis layer was added.

## OSM usage

The app uses the official HTTPS raster endpoint at tile.openstreetmap.org. Attribution remains visible whenever the OSM basemap is enabled. The client requests only tiles needed for the visible viewport; it does not prefetch or offer offline tiles. See the [OSMF tile policy](https://operations.osmfoundation.org/policies/tiles/) and [copyright and licence](https://www.openstreetmap.org/copyright).
