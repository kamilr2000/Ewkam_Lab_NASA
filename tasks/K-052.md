# K-052 — Połącz web z regionalnym API przez jawne CORS

Cel: umożliwić przeglądarce korzystanie z trybu live E-006, gdy web i API działają pod różnymi originami, bez awarii żądań i bez przejścia na dane syntetyczne.

Zakres: `apps/api/main.py`, `apps/api/tests/test_api_contract.py`, `apps/api/README.md`. Nie edytuj aktywnej ścieżki `apps/web/` Eweliny.

## Kroki

1. Dodaj jawny, konfigurowalny allow-list originów przez `TERRA_ANALOG_CORS_ORIGINS`, z ograniczonymi originami localhost dla lokalnego serwera Vite jako wartością domyślną.
2. Dopuść wyłącznie metody i nagłówki potrzebne katalogowi/profilom/wyszukiwaniu; nie włączaj wildcard ani credentials.
3. Dodaj sprawdzenia dozwolonego originu, niedozwolonego originu i preflightu POST oraz opisz ustawienie `VITE_API_BASE_URL` i serwera API.

## Kryteria odbioru

- [ ] Dozwolony dokładny origin dostaje nagłówki CORS dla katalogu i wyszukiwania; preflight POST akceptuje `Content-Type`.
- [ ] Niedozwolony origin i wildcard nie otrzymują dostępu; polityka nie używa cookies ani credentials.
- [ ] Realny regionalny przebieg API zachowuje kontrakt, wersję profilu/datasetu i jawny regionalny scope.
- [ ] Dokumentacja podaje odtwarzalne uruchomienie dwóch lokalnych serwerów oraz konfigurację osobnego originu produkcyjnego.

## Sprawdzenie

Uruchom testy API kontraktu na rzeczywistym katalogu i regionalnym wyszukiwaniu oraz testy preflight/CORS. Sprawdź dozwolony i niedozwolony origin. Uruchom `git diff --check`. Nie twierdź, że przeglądarka przeszła pełny przepływ bez rzeczywistego wywołania z originu web.

## Przebieg i dowody

Przed implementacją opublikuj osobny commit `tasks(K-052): IN PROGRESS` w `origin/main`, ustaw agenta, datę i gałąź. Następnie pracuj na `kamil/K-052-api-cors`; po każdej spójnej poprawce sprawdź, commituj i wysyłaj. `done` dopiero po kryteriach i integracji do `origin/main`.

## Powód dodania / wpływ

Odkryto podczas pilnego przeglądu E-006: commit web `f4648a5` wysyła live requests do `VITE_API_BASE_URL`, ale [konfiguracja Vite](../apps/web/vite.config.ts) nie ma proxy, a obecne [API](../apps/api/main.py) nie dodaje CORS. Web i API uruchamiane na osobnych lokalnych portach nie mogą więc przejść do prawdziwego przepływu w przeglądarce. Jest to P0, bo blokuje demo realnego regionalnego API; scoring i dane regionalne są już dostępne. CORS jest kontrolą przeglądarki, nie uwierzytelnieniem API.
