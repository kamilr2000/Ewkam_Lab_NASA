# E-020 — Odrzucaj odpowiedzi API niespójne z żądaniem

Cel: zapewnić, że wyniki live API dotyczą dokładnie wysłanego datasetu, zakresu, cech i parametrów mapy; nie prezentować odpowiedzi z innej konfiguracji jako wyniku bieżącego żądania.

Zakres: `apps/web/src/api/client.ts` oraz testy adaptera / harness wymagany do odtwarzalnego sprawdzania zgodności odpowiedzi.

## Kroki

1. W `parseSearch` porównaj `dataset_version`, echo `query` i top-level `response.scope` z `SearchRequest`: body, profile, scope type i `region_id`, tryb, cechy i wagi, `top_k` oraz `min_distance_km`. Uwzględnij jawnie znormalizowane wagi z odpowiedzi i odrzuć rozbieżność przez `ApiError`.
2. W `getAnalysisMap` porównuj `query.bbox`, `level` i `limit` z żądaniem zarówno dla `live`, jak i `synthetic`; prawidłowy `analysis_id` nie wystarcza przy niezgodnym oknie mapy.
3. Dodaj automatyczne przypadki pozytywne i negatywne dla rozbieżnego datasetu, scope, cech/wag, `top_k`, trybu/dystansu oraz bbox/level/limit. Zachowaj testy zgodności `analysis_id` i brak przełączenia na fixture po błędzie live.
4. Nie przenoś scoringu ani obliczania podobieństwa do przeglądarki. Zaktualizuj raport E-003 o opublikowany SHA i wyniki kontroli.

## Kryteria odbioru

- [x] Live odpowiedź search z innym datasetem lub dowolnym parametrem query jest jawnie odrzucona.
- [x] Live odpowiedź map z innym `bbox`, `level` albo `limit` jest jawnie odrzucona, nawet gdy `analysis_id` pasuje.
- [ ] Top-level `response.scope` (type i regionalne `region_id`, z zachowaniem null dla global) musi zgadzać się z requestem.
- [x] Automatyczne testy obejmują zgodne odpowiedzi i rozbieżności; HTTP error oraz błędne odpowiedzi live nie pokazują synthetic fixture.
- [x] Scoring pozostaje po stronie API, a zmieniony zakres jest przekazany do review na dokładnym SHA.
